# 캠퍼스 길찾기 — 건물을 관통하는 최단 경로 + 강의실까지

작성일 2026-11-12 (전면 개정) · 대상: 순천향대학교 아산 캠퍼스
저장소: https://github.com/coolzic0414/SW
기간: 7일 · 인원: 4명

## 1. 무엇을 만드는가

캠퍼스 지도 위에서 **지금 있는 곳 → 강의실 앞**까지 경로를 찍어주는 모바일 웹.

다른 지도 앱과 다른 점은 하나다. **건물을 통과한다.**

```
현재 위치 → 공학관 B305 · 도보 4분 10초

[지도]  ─── 실선: 바깥 길
        ━━━ 굵은 선: 건물 관통 구간 (지름길)
        ◆   출입구

1. 인간사랑관 쪽 길로 직진            40초
2. 공학관 서측 출입구로 들어가        [사진]
3. 1층 복도를 통과해 동측으로 빠져나감  35초  ← 돌아가는 것보다 1분 20초 빠름
4. 멀티미디어관 1층 출입구로 들어감    [사진]
5. 오른쪽 계단으로 3층               [사진]
6. 복도 끝 왼쪽, B305               [사진]
```

세 가지 조건으로 경로를 바꿀 수 있다.

- **비 안 맞는 길** — 실내·지하 연결통로 우선
- **계단 없는 길** — 다리 부상, 휠체어, 무거운 짐
- **지금 열린 문만** — 야간·주말에 잠기는 출입구 회피

## 2. 왜 하는가

캠퍼스 길찾기에는 **지도 앱이 모르는 정보가 셋** 있다.

**첫째, 건물을 통과할 수 있다는 걸 모른다.**
카카오맵·네이버지도는 건물을 장애물로 취급하고 바깥으로 돌아간다. 그런데 캠퍼스에서는 건물 1층 복도를 통과하는 게 훨씬 빠른 경우가 흔하다. 경사지 캠퍼스는 특히 그렇다 — 건물을 통과하면 언덕을 안 넘는다. 비 오는 날은 차이가 더 크다.

**둘째, 건물 안으로 들어가지 못한다.**
지도 앱은 건물 앞에서 끝난다. 정작 어려운 건 그다음이다 — 출입구가 여러 개고, 경사지 건물은 들어간 층이 1층이 아니고, 공학관처럼 복도가 回자로 돌면 방 번호 순서대로 가지지 않는다.

**셋째, 호실 코드가 어느 건물인지 모른다.**
시간표에는 `B305`만 적혀 있다. 1학년은 그게 공학관이라는 걸 모른다.

게다가 캠퍼스에 **건물을 부르는 방법이 세 가지**이고 서로 호환되지 않는다.

| 체계 | 예 | 쓰이는 곳 |
| --- | --- | --- |
| 캠퍼스맵 위치 번호 | `C03` 공학관, `B20` 의료과학관 | 학교 캠퍼스맵 |
| 강의실 코드(문자) | `U` 유니토피아관, `L` 향설도서관 | 시간표 강의실 칸 |
| 강의실 코드(숫자) | `9` 공학관, `3` 자연과학관 | 시간표 강의실 칸 |

`9115`는 공학관인데 캠퍼스맵에서 공학관은 `C03`이고, 시간표의 `B`는 산학협력관인데 캠퍼스맵의 `B20`은 의료과학관이다. **캠퍼스맵을 들고 `B`를 찾으면 엉뚱한 건물로 간다.**

**코드표 자체는 학교에 존재한다.** 다만 [국제교육교류처의 외국인 유학생 가이드](https://sgee.sch.ac.kr/usupport/guide09.php) 안에 **이미지 파일 하나**로 들어 있다. 한국 학생용 안내에는 없고, 검색에 걸리지 않으며, 이미지라 복사도 안 된다.

그래서 학생들이 "신입생을 위한 강의실 번호 위치" 정리글을 직접 만들어 돌려 쓴다. **정보가 없는 게 아니라 닿지 않는 곳에 있다는 것** — 이게 이 서비스가 메우는 공백이다.

## 3. 목표 / 비목표 / 실패 조건

### 목표

1. 캠퍼스 안 어디서든 출발해서 강의실 앞까지 경로가 나온다.
2. **건물 관통 지름길이 경로에 포함된다.** 전 건물에서 동작한다.
3. 조건별 경로를 제공한다 — 비 안 맞는 길, 지금 열린 문만. (계단 없는 길은 확인된 구간에 한해)
4. 지도 위 경로와 단계별 텍스트 안내가 한 화면에서 이어진다.
5. 예상 소요 시간이 실측보다 짧게 나오지 않는다.
6. **카카오맵 도보 경로보다 실제로 빠르다.** 숫자로 증명한다.

### 비목표

- 실내 실시간 위치 추적. 실내는 GPS가 안 잡힌다. 건물에 들어간 뒤로는 단계별 안내로 따라간다.
- 축척이 맞는 실내 평면도. 방향과 순서만 맞으면 된다.
- 차량·자전거·대중교통 경로.
- 시간표 연동, 혼잡도, 로그인.
- 캠퍼스 밖 경로. 정문 밖은 카카오맵에 넘긴다.

### 실패 조건 (돌아가도 실패로 본다)

- **안내가 틀려서 더 헤맨다.** 조사되지 않은 구간은 추측해서 안내하지 않고 "확인되지 않음"으로 표시한다.
- **계단 없는 길이라고 했는데 계단이 있다.** 안전 문제다. 직접 통과해 확인한 구간만 표시하고, 나머지는 아예 제시하지 않는다.
- **추정 데이터를 실측처럼 보여준다.** 모든 경로에 출처가 드러나야 한다.
- **지름길이라고 안내한 건물이 잠겨 있다.** 야간·주말 관통은 개방 시간을 확인한 건물만 허용한다.
- 지도는 예쁜데 경로가 카카오맵과 똑같다. 그러면 만들 이유가 없다.

## 4. 핵심 설계 판단

### 4-1. 카카오맵은 지도 표시용, 경로 계산은 우리 그래프

카카오맵 API로 경로를 받아올 수 없다. 카카오 길찾기는 차량·대중교통 중심이고, **캠퍼스 내부 보행로와 건물 내부는 데이터 자체가 없다.**

그래서 역할을 나눈다.

- **카카오맵**: 배경 지도, 마커, 경로 폴리라인 그리기, 로드뷰
- **우리 그래프**: 노드·엣지 직접 구축, 다익스트라로 경로 계산

이건 한계가 아니라 이 프로젝트의 존재 이유다. 카카오가 가진 데이터로 할 수 있는 일이면 만들 필요가 없다.

### 4-2. 데이터는 재학생 지식으로 채우고, 표본만 실측한다

현장을 전수 조사하지 않는다. 7일 안에 들어가지 않는다.

대신 **몇 년 다닌 재학생의 머릿속 지도를 1차 데이터로 쓴다.** 어느 건물을 어느 문으로 들어가 어디로 빠져나갈 수 있는지, 어느 문이 상시 잠겨 있는지는 재학생이 이미 안다. 이건 추측이 아니라 경험 데이터다.

지름길에 필요한 정보는 **"출입구 A에서 B까지 1층으로 통과 가능한가"** 뿐이다. 층별 구조를 몰라도 된다.

다만 세 가지 규칙을 지킨다.

1. **출처를 구분해 저장한다.** 모든 엣지에 `source: knowledge | measured`를 붙이고, 화면에 "직접 확인되지 않은 경로"로 표시한다. 사용자가 "여기 막혀 있어요"를 신고하는 버튼을 둔다
2. **아는 건물만 등록한다.** 모르는 건물의 관통은 비워 두고 커버리지 표에 드러낸다. 어설프게 추측해 넣는 게 가장 위험하다
3. **표본 5쌍을 실측한다.** 출발·도착 5쌍만 실제로 걸어서 재고 추정치와 비교한다. "추정 오차 평균 ±N초"가 나오면 나머지 추정치 전체가 신뢰를 얻는다. 한두 시간이면 된다

소요 시간은 옥외는 거리 기반, 실내 관통은 재학생 체감 시간으로 넣고, 표본 실측으로 보정 계수를 잡는다.

### 4-3. 나머지 데이터도 전부 책상에서 만든다

**호실 데이터는 공개 수업시간표에서 받는다.** `http://st.sch.ac.kr/?sch001` (학교 홈페이지 하단 '대학관련 사이트 바로가기' → 수업시간표)는 **로그인 없이** 열리고 개설 과목의 강의실이 들어 있다. 포털 경로는 종합정보시스템 → 학부학사행정 → 수업 → 수업시간표 조회.

단 이 화면은 **XPLATFORM(Tobesoft) 리치 클라이언트**라서 HTML 스크래핑이 안 된다(`.xadl`, `.xfdl`, `TOBE/System.js` 확인). 추출 경로를 쉬운 순서로 둔다.

1. **그리드 엑셀 내보내기** — XPLATFORM 그리드는 대개 지원한다. 있으면 여기서 끝
2. **네트워크 요청 재현** — F12 Network에서 조회 시 나가는 POST를 찾아 파라미터만 바꿰 호출. 응답이 구분자 기반 텍스트(SSV)면 파싱 가능
3. **화면 복사** — 조회 결과 드래그 복사. 원시적이지만 확실

**전수는 필요 없다.** 필요한 건 전체 강의 목록이 아니라 접두어 → 건물 매핑이고, 접두어는 10~20개뿐이다. 학과 몇 개만 조회해도 거의 다 나오며, **최악의 경우 재학생이 직접 채울 수 있는 분량**이다. 그래서 이 경로가 막혀도 메인 기능은 살아남는다.

실제 화면을 확인한 결과 **강의실 칸에는 코드만 나온다**(`U524`, `9115`). 건물명은 없다. 다만 **코드표를 학교 공식 자료로 확보했으므로**(부록 B) 매핑은 이미 끝났다. 포털에서 필요한 건 호실 목록뿐이고, 그마저도 전수가 아니어도 된다.

**옥외 보행로 그래프**는 카카오맵 위성사진으로 길을 따고, **로드뷰로 출입구 위치와 계단·경사를 확인**해 만든다. OSM에 보행로가 있으면 가져와 보정한다.

**출입구 사진은 찍지 않는다.** 카카오맵 SDK의 로드뷰 뷰어를 출입구 좌표·시점으로 띄우면 된다. 조사 항목에서 촬영이 빠진다.

결과적으로 현장에 나가는 일은 **표본 5쌍 실측(1~2시간)** 뿐이다.

### 4-4. 실내는 텍스트 안내까지만 한다

실내 평면도도, 실내 사진도 만들지 않는다. 7일 안에 들어가지 않는다.

실내 구간은 **재학생 지식 기반 텍스트 안내**로 끝낸다. "서측 출입구로 들어가서 중앙계단으로 3층" 수준이다. 아는 건물만 넣고, 모르는 건물은 **건물 앞까지 안내하고 멈춘다.**

정식 도면은 못 받는다. 건축물현황도는 이해관계인만 발급받을 수 있고, 학교 시설 부서도 보안 자료로 취급한다. 온라인에도 없다 — 학교 캠퍼스 페이지에는 캠퍼스맵과 VR CAMPUS만 있다. 피난안내도는 건물 내부 게시물이라 공개 의무가 없어 검색으로 나오지 않는다.

학교 홈페이지를 확인한 결과 **층별 안내도는 없다.** 캠퍼스맵은 건물 외부 배치도 이미지 한 장(`/_res/sch/img/img_intro_23.jpg`)이고 건물별 상세 페이지도 없다.

**VR CAMPUS**(https://pixmedia.space/vr/sch/index.html)도 확인했으나 **건물 내부가 없다.** 따라서 층별 구조를 얻을 공개 자료는 존재하지 않는다. 실내 안내는 전부 재학생 지식에 의존한다 — 아는 건물만, 텍스트로.

남은 가능성은 도서관 홈페이지 층별 안내와 학사 공지의 시험장 배치도 정도이고, 기대치는 낮게 둔다.

**계단 없는 길은 기억으로 보장할 수 없다.** 안전 문제이므로 기능을 격하한다 — "엘리베이터 위치 안내"로 바꾸고, 직접 통과해 확인한 구간만 `accessible: measured`로 표시한다. 확인되지 않은 구간은 계단 없는 경로로 제시하지 않는다.

### 4-5. 경로 계산을 브라우저에서 한다

그래프 전체를 JSON 하나로 컴파일해 앱과 함께 내려보내고, 다익스트라를 브라우저에서 돌린다. 노드 수천 규모라 성능 문제가 없다.

서버와 DB가 사라져서 배포가 정적 호스팅으로 끝나고, 데이터가 git에 텍스트로 남아 수정 이력이 추적되고 PR로 리뷰된다. 오픈소스 과제에 맞는 구조다.

**오프라인은 부분적으로만 된다.** 지도 타일은 온라인이 필요하다. 다만 건물에 들어간 뒤에는 지도가 필요 없고 사진과 안내문만 필요하므로, **실내 구간 자산을 미리 캐싱**하면 실용적으로는 문제가 없다. 이 한계는 솔직히 적는다.

### 4-6. 수집 도구를 먼저 만든다

실내 조사 비용이 이 프로젝트의 가장 큰 변수다. 스프레드시트로 받아 적으면 표기가 엇갈리고 병합이 지옥이 된다.

1일차에 **현장 수집용 모바일 화면**을 만든다. 노드 추가, 사진 촬영, 두 노드 연결, 스톱워치 구간 측정이 폰에서 끝나고 해당 건물의 YAML 파일을 직접 쓴다.

## 5. 데이터 모델

### 노드

| 필드 | 설명 |
| --- | --- |
| `id` | `out.W12`, `B.door.W`, `B.F3.J2`, `B.room.305` |
| `kind` | `outdoor` / `entrance` / `stair` / `elevator` / `ramp` / `junction` / `room` / `landmark` |
| `building` | 건물 코드. 옥외 노드는 없음 |
| `floor` / `floor_label` | 정수 + 표기 문자열. 경사지 건물은 둘이 어긋나므로 분리 |
| `coord` | 위경도. 옥외 노드와 출입구는 필수 (지도에 그려야 함) |
| `photo` | 사진. 출입구와 실내 분기점은 필수 |
| `landmark_hint` | `자판기 옆`, `게시판 맞은편` — 안내문에 섞는 기준점 |
| `open_hours` | 출입구만. 닫혀 있으면 경로에서 제외 |
| `surveyed_at` / `verified_by` | 조사 일자, 확인 인원 |

### 엣지

| 필드 | 설명 |
| --- | --- |
| `from` / `to` | 노드 id |
| `kind` | `outdoor_path` / `through_building` / `corridor` / `stair` / `elevator` / `ramp` / `underpass` / `skybridge` |
| `seconds` | 예상 소요 시간 |
| `indoor` | 실내 여부. 비 올 때 가중치 |
| `steps` | 계단 칸 수 |
| `slope` | 옥외 경사(평지/오르막/내리막). 오르막은 시간 가산 |
| `accessible` | 계단·문턱 없이 통과 가능한가 |
| `direction` | `straight`/`left`/`right`/`up`/`down` — 안내문 생성 |
| `open_hours` | 시간대에 따라 막히는 구간 |
| `requires_card` | 학생증 인증이 필요한 문·엘리베이터 |
| `source` | `knowledge`(재학생 지식) / `measured`(실측) — 화면에 출처를 표시한다 |
| `reported_blocked` | 사용자 신고 누적. 임계치를 넘으면 경로에서 제외 |

`through_building`이 이 프로젝트의 주인공이다. 출입구와 출입구를 1층으로 잇는 엣지다.

데이터는 `data/outdoor.yaml` + `data/buildings/<코드>.yaml`로 나눠 git에 둔다. 빌드 시 `graph.json`으로 합치고 검증을 통과해야 배포된다.

### 검증 (빌드 시 자동)

**차단 — 데이터가 깨진 경우**
- 접근성 모순 (`accessible: true`인데 `steps > 0`)
- 좌표 없는 옥외 노드·출입구
- 소요 시간 이상치 (옥외 1구간 3분 등)
- 스키마 위반, 존재하지 않는 노드를 가리키는 엣지
- `through_building` 엣지의 양 끝이 같은 건물의 출입구가 아님

**경고 — 조사가 덜 된 경우**
- 고립 노드, 층 연결 누락, 사진 없는 출입구
- 관통 가능 여부가 미조사인 건물

건물 파일에 `status: surveying | complete`를 둔다. `complete`로 올리면 경고가 차단으로 승격된다. **미완성은 허용하고, 완성 선언은 엄격하게** 받는다.

## 6. 호실 코드 해석

검색 한 줄이 이 서비스의 입구다. 1학년이 가진 정보는 `B305` 뿐이다.

1. **코드 + 숫자** (`B305`, `B-305`, `b 305`) → 건물 코드 테이블로 건물 확정, 앞자리로 층 추정
2. **이름 + 숫자** (`공학관 305`, `공대 305`) → 별칭 테이블. **학생 은어를 반드시 포함**한다(`공대`, `멀미관` 등). 공식 명칭만 넣으면 안 쓴다
3. **숫자만** (`305`) → 후보 건물 목록 제시
4. 실패 → 건물 목록에서 선택

층 추정이 건물마다 다를 수 있으므로 예외 테이블을 둔다. 추정값은 확인 카드로 보여준다 — "공학관 3층 B305, 맞나요?"

**코드 테이블은 두 벌 둔다.**

- `map_code` — 캠퍼스맵 위치 번호 (A01, C03, B20 …). 지도에 건물을 찍을 때
- `room_code` — 강의실 코드 (9, 3, U, L, ML …). 검색 해석에

`room_code` 테이블은 **학교 공식 자료로 확보했다**(부록 B). 추측하거나 역산할 필요가 없다.

파서가 받아야 할 형태는 둘이다.

1. **문자 + 숫자** — `U524`, `L507`, `ML325`, `RC220`. 두 글자 코드(`BI`, `ML`, `RC`)가 있으므로 **긴 코드부터 매칭**해야 한다. `ML325`를 `M` + `L325`로 읽으면 틀린다
2. **숫자만** — `9115`, `3209`. 첫 자리가 건물(9=공학관, 3=자연과학관), 둘째 자리가 층이다

층 추정은 코드를 떼고 남은 첫 자리로 한다. 추정값은 확인 카드로 보여준다 — "공학관 1층 9115, 맞나요?"

`X000`~`X017`(운동장·수영장·인턴십 등), `S/Y`, `E`는 강의실이 아니다. 검색되면 "강의실이 아닙니다"로 안내하고 경로를 내지 않는다.

## 7. 경로 탐색

옥외와 실내를 **하나의 그래프**로 합쳐 다익스트라를 돌린다. 기본 가중치는 `seconds`.

| 조건 | 처리 |
| --- | --- |
| 계단 없는 길 | `accessible: false` 엣지 제외. 도달 불가면 그 사실을 알린다 |
| 비 안 맞는 길 | `indoor: false` 엣지 비용 × 3, **야외 노출 시간을 별도 표시** ("야외 40초") |
| 지금 열린 문만 | 현재 시각에 닫힌 `open_hours` 제외 |
| 지름길 끄기 | `through_building` 엣지 제외. 카카오맵과 비교할 때 쓰는 대조군이 된다 |

경로는 **두 개를 나란히** 보여준다. "가장 빠른 길(4분 10초, 야외 90초)" vs "비 안 맞는 길(5분, 야외 0초)". 골라주는 것보다 고르게 하는 게 낫다.

### 소요 시간 추정

거리 ÷ 속도로 끝내지 않는다. 구성 요소를 나눈다.

- 옥외 평지: 거리 기반 + 실측 보정 계수
- 옥외 오르막: 가산 (경사지 캠퍼스라 무시하면 크게 틀린다)
- 실내 복도: 측정한 구간 시간
- 계단: 층당 고정값, **올라갈 때와 내려갈 때 다르게**
- 엘리베이터: 이동 시간 + 평균 대기 시간(고정 추정치)
- 문 통과, 방향 전환: 소액 고정 비용

쉬는 시간 10분에 갈 수 있는지를 판단하는 게 목적이므로 **실측보다 짧게 나와선 안 된다.** 불확실하면 넉넉한 쪽으로 올린다.

## 8. 화면

한 화면에서 옥외와 실내가 이어진다.

- **상단 — 카카오맵**: 경로 폴리라인. 바깥 길은 실선, **건물 관통 구간은 굵은 선과 다른 색**으로 눈에 띄게. 출입구에 마커
- **하단 — 단계 카드**: 위로 스와이프하면 올라오는 시트. 각 단계에 소요 시간, 실내 단계에는 **사진**
- **관통 구간 강조**: "여기서 1분 20초 단축" 을 명시한다. 이게 이 앱을 쓰는 이유라서 숨기면 안 된다
- 건물에 들어가면 지도는 접히고 사진 안내가 주가 된다

안내문은 규칙 기반으로 생성한다. 같은 방향의 연속 구간은 하나로 합치고, 방향 전환은 `direction` + `landmark_hint`를 붙여 쓴다.

## 9. 범위 — 두 단계 커버리지

7일, 4명이다. 전 건물 실내 조사는 불가능하다(건물 15동 × 평균 5층 = 75개 층, 층당 20~30분이면 40시간 이상). 그래서 **기능별로** 범위를 나눈다. 건물별이 아니다.

### 레벨 1 — 전 건물 (현장 조사 없음)

- 호실 코드 → 건물·층 해석 (**학교 포털 데이터로 전수**)
- 옥외 보행로 그래프 (위성 + 로드뷰)
- 전 건물 출입구 위치, 로드뷰로 모습 확인
- 건물 앞까지의 경로

**이게 메인 기능이다.** 1학년이 가장 많이 겪는 문제이고 데이터가 전부 온라인에 있다.

### 레벨 2 — 재학생이 아는 건물 (지식 기반)

- **건물 관통 지름길** — 차별점
- 실내 텍스트 안내 ("서측 출입구 → 중앙계단 3층")
- 확인된 구간의 엘리베이터 정보

아는 건물만 넣는다. 전 건물을 채우려 하지 않는다. 공학관처럼 길찾기 난이도가 높은 건물이 데모 가치가 크다.

### 레벨 3 — 표본 5쌍 (실측, 1~2시간)

- 카카오맵 대비 단축 시간 측정
- 추정 소요 시간 보정 계수
- 그 경로의 접근성 확인

### 커버리지를 숨기지 않는다

레벨 1만 있는 건물은 "이 건물은 실내 안내가 없습니다 — 출입구까지 안내합니다"를 명시한다. 추정 데이터는 "직접 확인되지 않음"으로 표시한다. 커버리지와 출처를 드러내는 게, 전부 안다고 말하는 것보다 낫다.

## 10. 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 지도 | **Kakao Maps JavaScript SDK** | 키 보유. 폴리라인·마커·로드뷰. 로드뷰는 옥외 데이터 구축에도 씀 |
| 프론트엔드 | React + TypeScript + Vite | 모바일 웹 |
| 경로 탐색 | 브라우저에서 직접 구현(다익스트라) | 카카오가 못 주는 부분. 라이브러리 없이 100줄 수준 |
| 데이터 | YAML → 빌드 시 `graph.json` | git 버전관리, PR 리뷰, DB 불필요 |
| 검증 | zod 스키마 + 커스텀 그래프 검사 | 깨진 데이터가 배포되지 않게 |
| 옥외 보조 데이터 | OpenStreetMap (보행로 있으면 가져와 보정) | 처음부터 손으로 찍는 수고를 줄임 |
| 오프라인 | PWA — 실내 사진·안내문·그래프 캐싱 | 지도 타일은 온라인 필요(한계 명시) |
| 배포 | Vercel 또는 GitHub Pages | 정적 호스팅으로 충분 |
| 테스트 | Vitest(탐색 로직) + Playwright(화면) | 경로 로직은 단위 테스트가 쉬움 |

카카오맵 API 키는 **도메인 제한과 쿼터**를 미리 확인한다. 배포 도메인을 허용 목록에 넣어야 한다.

## 11. 품질을 증명하는 방법

숫자 넷을 낸다. **1번이 이 프로젝트의 간판이다.**

1. **카카오맵 대비 단축 시간** — 출발·도착 **5쌍**을 뽑아, 우리 경로와 카카오맵 도보 경로를 **둘 다 실제로 걸어서** 측정한다. "건물 관통으로 평균 1분 20초 단축". 같은 측정으로 **추정 오차(±N초)**도 함께 낸다 — 나머지 추정 데이터의 신뢰 근거가 된다
2. **커버리지** — 전 건물 지름길 조사율, 레벨 2 호실 안내 가능 비율
3. **시간 예측 오차** — 실측과 예측의 평균 오차(초). 평가에 쓰는 값은 **여유분을 뺀 중앙 추정치의 오차**, 사용자에게 보여주는 값은 여유분 포함. 두 값을 분리해 두면 "넉넉하게 잡아 오차를 숨긴다"는 지적을 받지 않는다
4. **길찾기 성공률** — 1학년 5~10명에게 처음 가는 강의실을 찾게 하고, 우리 서비스 vs 카카오맵 + 학교 홈페이지로 성공률과 소요 시간 비교

- **레벨 2 대상 건물 4동** — 1학년 교양 집중 건물 + 서로 관통 경로를 보여줄 수 있는 조합
- **캠퍼스맵 번호(`A01`, `C03`)와 호실 접두어(`B305`)가 같은 체계인지** — 다르면 코드 테이블을 두 벌 둬야 함
- **수업시간표 화면에 엑셀 내보내기가 있는지, 강의실 칸에 건물명이 함께 나오는지** — 있으면 1일차가 빨라진다. 없어도 접두어는 지식으로 채울 수 있어 치명적이지 않다
- **카카오맵 API 키의 쿼터와 도메인 제한**
- **외부 공개 배포 가능 여부** — 공개 저장소에 건물 내부 사진을 올려도 되는지
- **1학년 테스트 참가자 확보 가능 여부**
